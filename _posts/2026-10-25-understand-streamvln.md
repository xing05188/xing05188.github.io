## 0. 先认识今天的主角

**StreamVLN** 是上海 AI Lab、香港大学、浙江大学、上海交大联合做的一个机器人导航系统，2025 年 7 月放出论文，中了 ICRA 2026。

它的全称是 *Streaming Vision-and-Language Navigation via SlowFast Context Modeling*，翻译过来是「基于慢快上下文建模的流式视觉与语言导航」。

名字里每个词都不简单，但拆开看很简单：

| 名字里的词 | 什么意思 |
|---|---|
| **Streaming（流式）** | 机器人的摄像头一直在拍，像看**直播**一样，画面源源不断进来 |
| **Vision（视觉）** | 用摄像头「看」 |
| **Language（语言）** | 听得懂人话，比如「出门左转，走到沙发那儿停下」 |
| **Navigation（导航）** | 自己找路过去 |
| **SlowFast（慢快）** | 它的核心创意：用**快记忆 + 慢记忆**两套系统管理看到的东西 |

一句话总结 StreamVLN 做的事：

> **给机器人一句话指令，它看着实时传回来的摄像头画面，一边想「我到哪了、该往哪走」，一边迈步，全程不卡。**
>
> —— 就像你蒙着眼（并不是）听朋友指挥走路，只不过机器人是「听着指令、看着画面」自己走。

## 1. 第一站：先搞懂三个词

在读任何论文之前，先建立三个概念。放心，都是字面意思。

### 1.1 具身智能（Embodied AI）

我们平时用的 ChatGPT、Claude，是「缸中之脑」：只能处理你发给它的文字和图片，自己没有身体，碰不到真实世界。

**具身智能**就是给 AI 装上身体——摄像头是眼睛，轮子或腿是脚，让它能在真实世界里**看**和**动**。扫地机器人、机器狗、人形机器人，都属于具身智能的研究对象。

### 1.2 VLN（视觉语言导航）

VLN 全称 Vision-and-Language Navigation，是具身智能里的一个经典任务：

> 你把机器人放进一个它**没来过**的房子里，对它说一句话——「走出卧室，穿过走廊，在厨房的冰箱旁边停下」——它必须靠自己理解这句话、靠自己观察环境，一步步走到目标位置。

难点在于：**没人告诉它地图**。它只知道起点和一句话，剩下的全靠现场看、现场想。

这件事比你想的难得多。人类小孩听一遍「去厨房冰箱那」就能找到，但机器人要同时回答一串问题：走廊在哪边？刚才那个门是不是走过了？现在该左转还是右转？指令里说的「沙发」和我眼前这个玩意是不是同一个东西？

### 1.3 VLN-CE（连续环境版 VLN）

VLN 最早是「传送带式」的：机器人站定一个点，环顾四周拍几张照片，然后「瞬移」到下一个点再拍。像下棋一样一格一格跳。

**VLN-CE（Continuous Environment，连续环境）** 取消了这种优待：机器人站在地上，摄像头连续拍摄，走一步看一步，画面是**连续的视频流**，跟真实世界一模一样。StreamVLN 要解决的就是 VLN-CE。

> {:.tip}
> **小比喻**：传送带式 VLN 像「翻绘本」，每页是一张照片；VLN-CE 像「看电影」，画面是连续的，你得自己决定每一秒干什么。

## 2. 第二站：一个真实任务长什么样

论文用的测试环境叫 **Matterport3D**：用专业设备把真实房子扫描成 3D 模型（客厅、卧室、办公室都有），放在一个叫 **Habitat** 的模拟器里跑——这样机器人撞墙了、掉沟里了都不用赔钱，可以反复实验。

测试用的指令来自两个著名数据集：

- **R2R（Room-to-Room，房间到房间）**：英语短指令，比如「出门左转，走到走廊尽头，进右边第二个门，停在桌子旁边」。路径平均 10 米左右。
- **RxR**：多语言指令（英语、印地语、泰卢固语），句子更长、描述更细，路径平均 15 米，更绕。

而机器人每一步能做的动作非常「原始」：**前进 25 厘米、左转 15 度、右转 15 度、停下**。就这四个。

> {:.note}
> 想象一下：朋友对你说「去楼下便利店买瓶水」，但你每步只能走 25 厘米、每次只能转 15 度，而且没人告诉你路线——这就是机器人面对的世界。

评价标准也很直接：

- **SR（Success Rate，成功率）**：最终停在了目标位置指定范围内，算成功。SR 56% 就是 100 次里成 56 次。
- **SPL（按路径长度加权的成功率）**：成功了但绕了一大圈，要扣分。它惩罚「走冤枉路」。
- **NE（Navigation Error，导航误差）**：结束时离目标还差几米。

这三个数字就是 VLN 领域的「考试成绩单」。

## 3. 第三站：难在哪？——机器人的「不可能三角」

现在我们知道任务了：**看连续视频流 + 听人话 + 实时做决定**。

难就难在，这三件事凑一起，撞上了一个「不可能三角」：

```
       看得细                   记得久
     （每一帧都                  （半小时前
      分析清楚）                 走过的路也记得）
          \                        /
           \                      /
            \                    /
             \                  /
              \                /
               \              /
                \            /
                 \          /
                  \        /
                   \      /
                    \    /
                     \  /
                   算得快（实时反应，不卡顿）
```

**看得细**，每一帧画面都要分析，可画面太多了，一秒好几十帧；
**记得久**，走了十分钟，总不能忘了起点长什么样、刚才那个三岔口在哪边；
**算得快**，机器人不能每走一步就「愣神十秒钟」再动，那不成痴呆了。

过去的办法是怎么做的，又为什么不行？

### 3.1 老办法一：从视频里挑几帧看

一帧都不落？算不过来。那就**采样**吧——一小时的路程，每秒只留一帧。

问题是：机器人做的是「低层次动作」（左转 15 度这种），需要看清楚**连续变化**。你抽帧看到的两个画面之间，可能正好错过了「该左转的路口」，而且画面跳变会让它误判速度。

> {:.warn}
> 就像看幻灯片猜足球走向——每一张都清楚，但球怎么运动的，断了。

### 3.2 老办法二：把图像「压扁」存着

看过的画面太多存不下，那就**压缩**：把 100 张相似画面的信息揉成一小撮「记忆豆」，以后只带豆子不带原图。

问题是：一压缩就丢细节。而且揉完之后，原来的画面细节没法还原——「刚才那个门是关着还是开着？」这种问题，压缩后的记忆豆答不上来。

### 3.3 老办法三：每一步都把全部历史重想一遍

这是最浪费的。机器人每走一步，就把「指令 + 我看过的所有画面 + 我做过的所有动作」整个打包，扔给大模型重新算一遍。

走了 100 步，第 100 步就要重算 100 步的历史。越走越慢，最后卡死。这还不算训练的时候——每步都重算，训练成本爆炸。

**StreamVLN 的论文摘要里那句话，说的就是这三个矛盾的破局：**

> 用一套「慢 + 快」的双记忆系统，同时做到看得细、记得久、算得快。

## 4. 中途休息：补两个必备概念

在讲 StreamVLN 的妙招之前，必须先补两个课。都很简单，而且讲完你会发现——原来就这么回事。

### 4.1 Token（词元）：AI 眼里的「积木」

大模型（就是 ChatGPT 背后那种）处理任何东西，都要先切成一小块一小块，每一块叫一个 **token**（词元）。

- 一段文字，按词/字切成 token；
- **一张图片，切成很多小方块（patch），每个方块变成 token**；
- 一段视频？那就是「很多张图片 × 每张很多块」，token 数量爆炸。

机器人看一帧摄像头画面，假设切成 256 个 token；看一分钟视频，就是几千个 token。**token 越多，模型越慢、越吃内存**——这就是一切麻烦的根源。

### 4.2 KV 缓存：AI 的「草稿纸」

大模型的心脏叫 Transformer，它工作分两步：

1. **预填充（prefill）**：把你给的所有 token（文字、图片块）读一遍，给每个 token 算一张「小抄」——它在数学上叫 key-value（KV）状态。这张纸条上记的是「这个 token 长什么样、和别人什么关系」。
2. **解码（decode）**：模型开始逐字生成回答。生成每个新字时，都要**翻以前所有 token 的小抄**，避免「金鱼记忆」。

问题来了：如果不存小抄，每生成一个字就要把全部历史重算一遍，慢死。所以工程上会把算过的 KV 小抄**缓存**起来，下次直接用——这套机制就叫 **KV 缓存（KV cache）**。

> {:.tip}
> **比喻**：KV 缓存就像你做数学题的草稿纸。每写一步都把中间结果记在纸上，下一行直接接着用；要是每写一行都把前面的推导重算一遍，你早就崩溃了。

StreamVLN 玩的就是这张草稿纸——**怎么存、存哪些、什么时候扔**。

## 5. 第四站：核心创意——慢快双记忆

现在，高潮部分。

先问一个问题：**人是怎么做到一边走路一边聊天的？**

你走在上班路上，脑子里其实有两套东西在同时工作：

- **手头正忙的**：眼前这条马路、对面走来的人、刚变红的红灯——**最新的几秒**，调用极快，支撑你当下的每一步；
- **大概记得的**：「我是从哪个地铁口出来的」「走过两个路口了」「公司在河边那栋楼」——**几分钟到几小时前的压缩记忆**，细节模糊但足够你规划大方向。

前者是**工作记忆**（快），后者是**长期记忆**（慢）。

StreamVLN 的「SlowFast（慢快）」设计，就是照着这个直觉来的：

```
          ┌─────────────────────────────────────┐
          │           机器人（StreamVLN）          │
          │                                     │
  摄像头 →│  ┌──────────────┐    ┌───────────┐  │
  视频流  →│  │  快记忆        │    │  慢记忆    │  │
          │  │  滑动窗口      │←──→│  体素剪枝  │  │
          │  │  最近几轮原样  │    │  压缩存档  │  │
          │  │  保存          │    │           │  │
          │  └──────┬───────┘    └─────┬─────┘  │
          │         ↓                  ↓        │
          │         └────── 合并 ──────┘        │
          │                 ↓                   │
          │            生成一个动作             │
          │      （前进 / 左转 / 右转 / 停）      │
          └─────────────────────────────────────┘
```

下面把它拆开讲。为了讲得舒服，论文把整个导航过程设计成了一个**多轮聊天**。

### 5.1 把导航变成「多轮聊天」

这是 StreamVLN 的第一个设定：**导航 = 对话**。

每一「轮」聊天 = 机器人**看一张新画面（观察）+ 说一个动作**。整段导航就是一场超长对话：

> **系统**：你的指令是：「出门左转，走到沙发旁边停下」。
> **机器人**（第 1 轮）：〔看：眼前是卧室门〕→ 动作：前进
> **机器人**（第 2 轮）：〔看：走廊，左边有扇门〕→ 动作：左转
> **机器人**（第 3 轮）：〔看：沙发出现了〕→ 动作：前进
> **机器人**（第 4 轮）：〔看：到沙发边了〕→ 动作：停

这个设定妙在：大语言模型最擅长的就是「多轮对话」，把导航塞进对话格式，就能白嫖 ChatGPT 同款技术的全部积累。

### 5.2 快记忆：滑动窗口 KV 缓存

对话一轮轮进行，KV 草稿纸越来越厚，怎么办？

StreamVLN 的办法是**滑动窗口**：只在内存里保留**最近 N 轮对话**（论文里 N=8 效果最好）的 KV 缓存。窗口就像一列火车，新轮进来，旧轮被挤出去。

> **快记忆 = 最近 8 轮的完整小抄，原样保存，随取随用。**

被挤出窗口的旧内容也不是直接扔——里面有用的东西会「流转」到慢记忆里（下面讲）。而且窗口一旦滑动，被卸载的 KV 状态会被**保存到硬盘/内存池**，需要时还能捞回来复用。

这个设计直接干掉了「每步重算全部历史」的浪费：**每一步，模型只需要给「新看的那一帧」算小抄，历史的小抄都在缓存里躺着**。预填充的计算量从「全部历史」降到「一帧」，延迟自然就稳了。

### 5.3 慢记忆：3D 体素剪枝

窗口只有 8 轮，可导航经常要走几百轮。八轮之前的世界长什么样？全忘了？

不。**旧画面会被压缩进「慢记忆」**。这里就是论文最巧的一步：**基于体素（voxel）的 3D 空间剪枝**。

先解释「体素」：像素是 2D 图片的小方格，**体素就是 3D 空间的小立方体**，可以理解成 Minecraft 的方块。

流程是这样的：

1. **把 2D 画面「拍」回 3D 世界**：机器人有深度信息（每个像素离我多远），所以能把一帧画面里的每个图像块（patch token）反投影到它所在的 3D 位置——这个门在左前方 2.3 米处，那张沙发在正前方 1.1 米处；
2. **把空间切成体素网格**：以 3D 厘米/分米为单位，把周围空间切成无数小立方体；
3. **一个格子只留最新的**：第 10 分钟看到的门和第 2 分钟看到的门，如果反投影后落进同一个体素格子，就**只保留最近那一帧的 token**，旧的删掉。

> {:.tip}
> **比喻**：这就像你旅游时拍照。同一个景点拍了一百张，回家整理时你只会留下最清楚的那几张，还按地点归好相册。StreamVLN 的慢记忆，就是按「3D 位置」自动整理的相册——同一个地方只留最新鲜的一张。

这样做有四个好处，个个戳中痛点：

- **不改变已计算的 token**：这是「免训练（training-free）」的操作，只是删格子，不动任何特征，所以不会损害模型能力；
- **复用卸载的 KV**：删掉的 token，其 KV 小抄已经被存到池子里，慢记忆可以把它们捞回来接着用，不用重算；
- **保留高分辨率**：注意，它删的是「重复的空间记忆」，而不是把画面本身压扁——眼前该看的多清楚还是多清楚；
- **效果反而更好**：论文实验里，剪掉 20% 的冗余 token 后，R2R 的成功率不降反升（+1.2%）。

> {:.note}
> **为什么按 3D 空间剪、不按时间剪？** 机器人导航的视频有个特点：它往前走，很多画面拍的是**同一块地方的重复观察**——同一个走廊，第 30 秒和第 50 秒各拍了一次。按时间采样会漏掉「不同时间看同一空间」的冗余；按 3D 空间剪，一剪一个准。

### 5.4 合起来：一步是怎么走出来的

现在把快慢记忆合起来，看机器人走一步的完整流程：

1. 摄像头传来**新一帧画面**；
2. 快记忆（最近 8 轮的 KV 缓存）**直接可用**，新帧只需算自己的小抄；
3. 新帧的 token 反投影进 3D 体素网格，**同一格子里的旧 token 被剪掉**，只留最新的——慢记忆完成一次「慢更新」；
4. 模型基于「快记忆 + 慢记忆」生成动作 token：「前进」；
5. 动作追加进对话历史，窗口滑动，新的一轮开始。

全程**上下文规模有上限、计算量每步恒定**——这就是论文说的「bounded context size and inference cost（有界的上下文与推理成本）」。走 10 分钟和走 10 小时，每一步的反应速度一样快。

**这就是「慢快」二字的全部含义**：

| | 快记忆 | 慢记忆 |
|---|---|---|
| 对应人的 | 工作记忆 | 长期记忆 |
| 存什么 | 最近几轮对话，原样小抄 | 压缩后的历史空间记忆 |
| 更新方式 | 每轮滑动，即取即用 | 窗口满了才整理一次 |
| 关键技术 | 滑动窗口 KV 缓存 | 3D 体素空间剪枝 |
| 回答的问题 | 「我现在眼前是什么、刚才几步干了啥」 | 「这条走廊我是不是来过、那个路口在哪边」 |

## 6. 第五站：这么聪明的系统，怎么训练出来？

看到这你可能会问：滑动窗口、体素剪枝，这些是设计好的还是学出来的？

答案是：**核心框架是设计好的工程巧思（免训练），模型本身只用了很常规的两阶段训练**。

### 6.1 底座：一个视频大模型

StreamVLN 站在巨人肩膀上——底座是 **LLaVA-Video**（一个 7B 规模的视频多模态大模型，语言部分是 Qwen2-7B）。

「7B」指 70 亿参数，可以粗略理解为模型的「脑容量」。视频大模型本来就具备「看视频 + 对话」的能力，StreamVLN 做的事是：**把它扩展成一个「视觉-语言-动作」模型（VLA）**——以前它看完视频只会聊天，现在看完视频要输出「前进/左转/右转/停」。

### 6.2 第一阶段：跟着专家抄作业

先把导航数据「喂」给模型微调。数据从哪来？

**450K 条「专家轨迹」**——在 Matterport3D 的 60 个真实房屋扫描环境里，由「标准答案导航员」（知道最优路线的那种程序）示范出来的录像：每一步看到什么画面、做了什么动作，全部记录。来源包括 R2R、R2R-EnvDrop、RxR、ScaleVLN 四个数据集。

就像驾校新手看教练开车：**看画面 → 看动作 → 模仿**。这一阶段模型学会了「导航的基本动作」，但有个毛病：教练永远走正确路线，学生没见过错误，自己一上路就慌。

### 6.3 第二阶段：自己开，教练副驾纠错

这时候 VLN 领域的经典算法 **DAgger（Dataset Aggregation，数据集聚合）** 登场了。

**DAgger 的思路一句话：让学生自己开，开到偏了，教练在旁边示范「这时候应该怎么开」，把纠错录像也加进训练集。**

具体到 StreamVLN：让第一阶段训练好的模型自己在模拟器里跑（它会犯错、会绕路、会撞墙），然后让「标准答案导航员」在模型犯错的那些状态下示范正确动作，收集 **240K 条纠错数据**，拿回去联合训练。

> {:.warn}
> **为什么纠错数据这么值钱？** 消融实验显示：加上 DAgger 数据，成功率暴涨 **+5.3 个百分点**（SPL +4.1）；去掉它，性能显著下降。这是全配方里最大的单一增益——「见过错误」比「只会背标准答案」重要得多。

### 6.4 顺带防「偏科」

只拿导航数据练，模型容易「偏科」——导航越来越强，但把底座大模型的通用视觉理解能力（认东西、答问题）练废了。所以第二阶段还掺了通用数据一起练：

- **248K 视频问答样本**（来自 LLaVA-Video-178K 和 ScanQA 两个数据集）：比如「描述一下右边的画」「蒙娜丽莎和爱因斯坦哪幅在左边」——保住它「看懂世界」的通用能力；
- **230K 交错图文样本**（来自 MMC4）：图一段文一段的网页式内容，保住多轮对话的手感。

最终数据配方大致是这样：

| 数据类型 | 数量 | 作用 |
|---|---|---|
| 导航专家轨迹（R2R/EnvDrop/RxR/ScaleVLN） | 450K | 学基本导航技能 |
| DAgger 纠错轨迹 | 240K | 学会从错误中恢复 |
| 视频问答（LLaVA-Video-178K + ScanQA） | 248K | 保住通用时空推理 |
| 交错图文（MMC4） | 230K | 保住多轮对话能力 |

训练成本：两个阶段各训 1 个 epoch（一轮），合计约 **1500 张 A100 显卡小时**。

## 7. 第六站：成绩怎么样？

### 7.1 仿真 benchmark：SOTA

在两个公开 VLN-CE 基准上，StreamVLN 拿了 **RGB-only（只用彩色摄像头、不用深度仪等其他传感器）方法里的最好成绩**：

| 基准 | 成功率 SR | 路径加权成功率 SPL | 导航误差 NE |
|---|---|---|---|
| **R2R（未见环境）** | **56.9%** | **51.9%** | 4.98 米 |
| **RxR（未见环境）** | **52.9%** | **46.0%** | 6.22 米 |

几个值得记住的对比：

- **数据效率惊人**：对比方法 HMAT 用了 300 万条轨迹训练，StreamVLN 只用了 ScaleVLN 的一个 15 万条小子集，就超过了它。
- **不挑传感器**：只用普通 RGB 摄像头就能打平依赖全景图、深度图、里程计等方法。
- **顺带解锁了新技能**：在 ScanQA（3D 场景问答）测试里也超过了 NaviLLM、NaVILA 等通用导航模型——「边走边答」它也会。

> {:.note}
> 「未见环境（Val-Unseen）」是 VLN 的标准考法：训练时没见过这些房子，测试时直接进新房。56.9% 的意思就是——**在一栋从未见过的房子里，听一句没见过的话，它能独立走对一半以上。**

### 7.2 真机：机器狗上岗了

光在模拟器里牛不算牛，StreamVLN 真的上了实体机器人：

- **平台**：宇树（Unitree）**Go2 机器狗** + Intel RealSense **D455 深度摄像头**；
- **部署方式**：机器狗负责看和走，「大脑」在一台带 **RTX 4090** 显卡的远程工作站上，画面无线传输过去推理，再把动作指令传回来；
- **速度**：平均生成 4 个动作只要 **0.27 秒**，室内通信延迟 0.2 秒、室外 1 秒——**流畅到可以实时遥控**。

论文里展示了它在客厅、卧室、办公室、商场、人行道等各种场景的导航，甚至能执行「超长时程」任务（走很久很远），还能在导航途中回答视觉问题（「右边那幅画是什么？」「蒙娜丽莎和爱因斯坦哪个在左边？」）。

## 8. 一张图总结全文

如果上面全都忘了，记住这张「人话流程图」就够了：

```
  人给一句话指令
       │
       ▼
  ┌─────────────┐
  │ 机器人看直播  │  ← 摄像头画面连续进来（视频流）
  └──────┬──────┘
         │ 每一轮 = 看一帧 + 做一个动作
         ▼
  ┌───────────────────────────┐
  │  快记忆：最近几轮原样小抄   │  ← 滑动窗口 KV 缓存，即取即用
  │  慢记忆：历史按 3D 位置存档 │  ← 体素剪枝，一个位置只留最新
  └─────────────┬─────────────┘
                │
                ▼
        输出：前进 / 左转 / 右转 / 停
                │
                ▼
   走一步 → 新画面进来 → 进入下一轮（循环）
```

StreamVLN 的全部精髓，就是中间那个框：**最近的事记得清清楚楚（快），久远的事按空间归档压缩（慢）**——跟人走路时脑子干的事，一模一样。

## 9. 小白术语词典

| 术语 | 人话解释 |
|---|---|
| **具身智能** | 有身体（摄像头+轮子/腿）的 AI，能在真实世界看和动 |
| **VLN** | 视觉语言导航：听一句人话，自己在陌生环境找路 |
| **VLN-CE** | 连续环境版 VLN：看实时视频流走一步看一步，不是传送带跳格子 |
| **Habitat** | Meta 出的 3D 室内仿真平台，机器人的「练功房」 |
| **Matterport3D** | 真实房屋的 3D 扫描数据集，机器人的「考场」 |
| **R2R / RxR** | 两个著名 VLN 指令数据集，前者英语短指令，后者多语言长指令 |
| **Token** | AI 处理信息的最小积木；图片切成小方块，每块变若干 token |
| **KV 缓存** | Transformer 的「草稿纸」，存已算过的中间结果，避免重复计算 |
| **预填充 / 解码** | 先读输入算小抄（预填充），再逐字生成（解码） |
| **滑动窗口** | 只保留最近 N 轮对话的小抄，旧的挤出去 |
| **体素（voxel）** | 3D 空间的小立方体，Minecraft 方块那种 |
| **Token 剪枝** | 把没用的 token 删掉，省算力；这里按 3D 空间位置剪 |
| **Video-LLM** | 能处理视频的大语言模型，StreamVLN 的底座 |
| **VLA 模型** | 视觉-语言-动作模型：看图听指令，直接输出动作 |
| **DAgger** | 让学生自己开、教练在副驾纠错的模仿学习算法 |
| **SR / SPL / NE** | 成功率 / 按路径长度加权的成功率 / 离目标还差几米 |
| **免训练（training-free）** | 不用重新训练模型、设计好即插即用的工程技巧 |
| **SOTA** | State-of-the-Art，当前最好水平 |

## 写在最后

StreamVLN 这篇论文最值得学的，其实不是某个具体技巧，而是它**提问题的方式**：它没有把「长视频」当成一个要硬扛的算力问题，而是先问——「人是怎么做到边走边看边想的？」然后把答案（工作记忆 + 长期记忆）翻译成了工程语言（滑动窗口 + 体素剪枝）。

好的研究大多如此：从一个每个人都懂的生活直觉出发，最后落到一行公式里。
